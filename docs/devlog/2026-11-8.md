# Devlog: Milestone 2 (Part 2) - Depth Buffering, True 3D, and ImGui Texture Visualization

**Date:** November 8, 2026
**Engine Architecture:** Vulkan 1.3 (C++ RAII), Dynamic Rendering, Volk
**Current State:** Fully functioning 3D depth testing, Backface Culling, and Real-time Depth Buffer visualization in Dear ImGui.

## Overview

The objective of today's session was to transition the engine from a 2D projection layer into a true 3D environment. This required implementing a Depth Buffer (Z-Buffer) for proper geometric occlusion, rendering complex 3D geometry (RGB Cube), and creating a pipeline to visualize raw Vulkan attachments inside the Dear ImGui debug interface.

Visualizing the depth buffer proved to be highly complex due to strict Vulkan specifications regarding memory layouts, attachment usages, and non-linear depth mathematics.

## Work Completed

### 1\. 3D Geometry \& Culling

* Upgraded the static 2D quad to a fully indexed 3D RGB Cube (8 vertices, 36 indices) to accurately test depth sorting and camera orientation.
* Implemented Backface Culling (`vk::CullModeFlagBits::eBack`) and `eCounterClockwise` front-face winding in the Rasterization State to resolve visual "inside-out" optical illusions caused by overlapping double-sided faces.

### 2\. Depth Buffering implementation

* Integrated a `vk::Image` and `vk::ImageView` utilizing `vk::Format::eD32Sfloat`.
* Configured `vk::PipelineDepthStencilStateCreateInfo` with `vk::CompareOp::eLess` to ensure closer fragments correctly occlude distant ones.
* Updated the `renderFrame` command buffer recording to clear the depth attachment to `1.0f` and transition the image layout using `vk::ImageMemoryBarrier2`.

### 3\. ImGui Depth Visualization Pipeline

* Successfully passed a Vulkan Image View to Dear ImGui by splitting the frame into two distinct Dynamic Rendering passes:

  1. **3D Scene Pass:** Renders the cube and writes to the Depth Attachment.
  2. **UI Pass:** Renders ImGui, reading the previously written depth buffer as a texture.
* Implemented explicit layout transitions between the passes (from `eDepthAttachmentOptimal` to `eShaderReadOnlyOptimal`) using `vk::AccessFlagBits2::eDepthStencilAttachmentWrite` and `vk::AccessFlagBits2::eShaderRead`.

## Technical Challenges \& Resolutions

### Issue #1: The "Inside-Out" Optical Illusion

* **Problem:** When rendering flat overlapping quads or un-culled cubes, the engine appeared to reverse depth based on the camera's viewing angle.
* **Solution:** This was a visual illusion caused by the lack of lighting and backface culling. Updating the rasterizer to cull back-facing triangles (`eBack`) immediately solidified the 3D geometry.

### Issue #2: Invalid Depth Format Cast (Silent GPU Rejection)

* **Problem:** The depth format was incorrectly assigned by casting the return value of `device.findMemoryType` directly into a `vk::Format`. This resulted in the GPU treating the depth buffer as a color format (e.g., `VK\_FORMAT\_R4G4B4A4`), causing silent driver-level rejections when used as a depth attachment.
* **Solution:** Hardcoded the depth format to the industry-standard `vk::Format::eD32Sfloat`, ensuring proper depth-stencil validation.

### Issue #3: Depth Memory Discard (`eDontCare`)

* **Problem:** The depth texture appeared completely blank (transparent) inside the ImGui debug window, despite successful descriptor generation.
* **Solution:** In the `vk::RenderingAttachmentInfo` for the depth buffer, `StoreOp` was mistakenly set to `eAttachmentStoreOp::eDontCare`. This instructed the GPU to discard the depth memory immediately after the 3D pass. Changed this to `eStore` to preserve the depth data for the subsequent UI render pass.

### Issue #4: Component Swizzling on Depth Attachments

* **Problem:** Attempting to force the Alpha channel to `1.0` using `vk::ComponentSwizzle` on the Depth Image View resulted in a blank output.
* **Solution:** The Vulkan specification strictly prohibits using Swizzled Image Views as Render/Depth Attachments. Removed the swizzle from the main depth attachment. Since the raw depth value is stored in the Red channel, ImGui renders it as grayscale natively with a red tint (or white on a white background).

### Issue #5: Non-Linear Depth Clustering

* **Problem:** Once correctly rendered in ImGui, the depth buffer appeared entirely solid.
* **Solution:** Depth values in a standard perspective matrix scale non-linearly, clamping very close to `1.0` (White) almost immediately. To visually verify the depth buffer, the camera's Far Plane in `glm::perspective` was temporarily reduced from `100.0f` to `10.0f`. This constrained the depth mapping, successfully revealing the gradient silhouette of the cube.
