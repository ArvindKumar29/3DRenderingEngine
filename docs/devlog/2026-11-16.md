# Engine Devlog — November 16, 2026

**Milestone 3 (Phase 4): Texture Pipeline — Descriptors \& First Render**

## 1\. Overview

Today's session marked a massive milestone: the first successful texture render on our 3D geometry! We bridged the gap between the GPU-side VRAM image (loaded yesterday) and the graphics pipeline using Vulkan's Descriptor system. While the texture is officially rendering, we identified a geometry-based UV mapping artifact that will be resolved in the next session.

## 2\. Features Implemented

### Descriptor Pipeline (The Bridge)

* **Sampler Creation:** Created a `vk::Sampler` with `eLinear` (or `eNearest`) filtering to dictate how the texture behaves when scaled.
* **Descriptor Set Layout:** Configured a `vk::DescriptorSetLayoutBinding` for a `COMBINED\_IMAGE\_SAMPLER` at `binding = 0` for the Fragment Shader, and attached this layout to the main `PipelineLayout`.
* **Descriptor Pool \& Allocation:** Initialized a `vk::DescriptorPool` and successfully allocated a `vk::DescriptorSet` from it.
* **Updating the Set:** Used `vk::WriteDescriptorSet` and `vk::DescriptorImageInfo` to plug the loaded `imageView` and `sampler` directly into the allocated descriptor set.
* **Render Loop Integration:** Bound the descriptor set to the graphics pipeline before the draw call using `vkCmdBindDescriptorSets`.

### Shader Updates (GLSL)

* **Vertex Shader (`.vert`):** Added a new `layout(location = 2) in vec2 inTexCoord` attribute and forwarded it to the fragment shader.
* **Fragment Shader (`.frag`):** Declared `layout(binding = 0) uniform sampler2D texSampler` and utilized the `texture()` function to sample pixel colors using the interpolated UV coordinates.

## 3\. Bug Fixes \& Learnings

* **Vulkan-HPP RAII vs Raw Handles:** Encountered compiler error `C2440` (cannot convert `vk::raii::DescriptorSetLayout` to `const vk::DescriptorSetLayout`). Learned that Vulkan-HPP RAII objects must be dereferenced using `\*` (e.g., `\*descriptorSetLayout`, `\*texture.imageView`) to extract the raw C-style handles required by certain functions.
* **File Path Case-Sensitivity:** Fixed an `stbi\_load` crash caused by an incorrect relative path and case sensitivity (`Assets` vs `assets`).

## 4\. Known Issues (Pending)

* **The "UV Smearing" Glitch:** The texture currently renders but looks heavily distorted and stretched across the cube. It is also tinted with neon colors (purple, cyan, etc.).

  * *Cause 1 (Geometry):* We are currently using only **8 shared vertices** for the entire cube. UV coordinates cannot map correctly across 90-degree corners when faces share the exact same vertex data.
  * *Cause 2 (Shaders):* The fragment shader is currently multiplying the sampled texture color with the underlying vertex colors.

## 5\. Next Steps

* **Expand Geometry:** Rewrite `Buffers.h` to define the cube using **24 unique vertices** (4 vertices per face $\\times$ 6 faces) so each face can have its own dedicated UV coordinate mapping (`0.0, 0.0` to `1.0, 1.0`).
* **Shader Cleanup:** Remove the vertex color multiplication in the fragment shader to display the un-tinted, pure texture image.
