# Engine Devlog — November 15, 2026

**Milestone 3 (Phase 3): Texture Pipeline — GPU Image \& VRAM Transfer**

## 1\. Overview

Today's session concluded the core Vulkan texture loading pipeline. We transitioned the raw pixel data residing in the CPU-visible VMA staging buffer directly into high-speed, device-local VRAM. This involved creating the necessary Vulkan Image and ImageView objects, and choreographing the memory transfer using Sync2 pipeline barriers and one-time command buffers.

## 2\. Features Implemented

### GPU Image \& View Creation

* Set up a `vk::ImageCreateInfo` configured for a 2D image with `eR8G8B8A8Srgb` format to perfectly match `stb\_image`'s 4-channel byte output.
* Applied bitwise usage flags: `eTransferDst` (to receive data from the staging buffer) and `eSampled` (to be read by the fragment shader).
* Utilized `vmaCreateImage` for device-local allocation (`VMA\_MEMORY\_USAGE\_AUTO`). Bridged the C++ `vulkan\_raii` structs with the C-based VMA API using `reinterpret\_cast<const VkImageCreateInfo\*>`.
* Generated a `vk::raii::ImageView` to expose the `eColor` aspect of the image to the rendering pipeline.

### GPU Data Transfer \& Sync2 Barriers

* Recorded a one-time submit command buffer (`eOneTimeSubmit`).
* **Transition 1:** Used a custom `transitionImageLayout` wrapper (backed by `vk::ImageMemoryBarrier2`) to shift the image from `eUndefined` to `eTransferDstOptimal` layout.
* Executed `cmdBuffer.copyBufferToImage()` to push the pixels from the VMA staging buffer into the device-local image.
* **Transition 2:** Transitioned the image layout from `eTransferDstOptimal` to `eShaderReadOnlyOptimal` so the fragment shader can sample it.
* Submitted the command buffer directly to the Graphics Queue without unnecessary semaphore waits (since this is a standalone memory operation, not tied to the swapchain render pass).

### Memory Hygiene

* Enforced a `device.graphicsQueue.waitIdle()` to stall the CPU until the GPU finished the transfer.
* Safely deleted the middleman: called `vmaDestroyBuffer` to free the RAM staging buffer and its allocation immediately after the transfer completed.

## 3\. Next Steps

* **Geometry Update:** Add `glm::vec2 texCoord` to the `Vertex` struct and update vertex input binding descriptions.
